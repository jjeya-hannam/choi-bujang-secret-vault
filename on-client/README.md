# 내 보안 Agent 시작 틀 0.2.14

이 보안 Agent는 회사 직원이 자기 로그인 상태, 업무 앱 접속 결과, 최근 접속 기록과 보안 경보를 보는 보안 앱입니다. 13단계부터 22단계까지 이 프로젝트 하나로 화면을 채워 가며 완성합니다. 처음이라면 docs/GETTING_STARTED_STUDENT.md부터 읽습니다. 무엇을 왜 만드는지와 단계별 순서가 그 문서에 있습니다.

이 시작 틀을 받은 것만으로 단계를 통과하지 않습니다. 단계마다 docs/STUDENT_PROMPTS.md의 안내를 수업용 AI에 붙여 넣어 student/extension.mjs를 고치고, 화면에서 확인하고, 커밋한 뒤 ALEPH에 제출합니다. 제출하면 서버가 그 커밋의 코드를 받아 AI가 단계 과제 기준으로 읽고 판정합니다. 코드를 실행해서 판정하지 않습니다.

## 켜기

검수 환경은 Node.js 24.19.0이며 외부 npm 의존성이 없습니다. 이 폴더의 PowerShell에서 아래를 실행하고 PC 브라우저로 http://127.0.0.1:5189 를 엽니다. 자세한 켜기·끄기·다시 켜기는 docs/STUDENT_LAUNCH_GUIDE.md에 있습니다.

    powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1

npm start도 같은 서버를 켭니다. 기본 실행은 실제 회사 시스템(기존 엔진)에 연결되지 않은 상태입니다. npm run demo는 예제 자료로 화면을 보여 줄 뿐이며 실제 연결이나 성취가 아닙니다. npm run check는 student/extension.mjs의 문법만 확인합니다.

## 지킬 것

- 기존 1~3차 프로젝트와 학생 파일은 지우거나 덮어쓰지 않습니다. 새 폴더에서 시작하거나, 이미 하던 프로젝트를 이어 씁니다.
- AI 열쇠·비밀번호·토큰을 코드, 커밋, 캡처, 도움정보에 넣지 않습니다. 주소나 열쇠를 직접 입력하는 칸도 만들지 않습니다.
- .env.example에는 비밀 없는 설정만 있습니다.

## 18단계 저장점 · 근거가 있는 AI 사건 설명

2026-10-23 확인한 원격 main `57c9358ae54e33c6555183ed55e38e6ed1d18b63`에는 on-client가 없어 사용자 승인에 따라 공식 `alekov-starter-0.2.14.zip`을 새 on-client 폴더에 추가했습니다. 기존 1~12단계 자료실과 XDR 파일은 변경하지 않았습니다. 이전 13~17단계 학생 구현 소스는 이 저장소에서 찾지 못했으며 새 시작 틀의 해당 학생 함수는 구현 대기 상태입니다. 심판의 과거 통과 기록을 복원 구현의 증거로 취급하지 않습니다.

학생 구현은 `on-client/student/extension.mjs`의 renderExplanation입니다. 현재 사건의 모든 근거 ID와 근거 문장, 규칙 ID와 문장, 접속·세션·기기의 unknown을 표시합니다. 실패·근거 부족·불일치·이미 실행했다는 응답에는 성공 속성을 붙이지 않습니다. 제안에는 이유와 사람 확인·미실행을 표시하며 학생 영역에 실행 버튼을 만들지 않습니다. 오류는 허용 코드의 고정 문구로 표시하고 textContent만 사용합니다. 늦은 응답 폐기는 제공 호스트의 generation 검사와 요청 취소를 유지합니다.

검증: `cd on-client && npm test`로 합성 DOM 검사 12건 통과. 로컬 예제 서버의 `/`, `/student/extension.mjs`, `/api/me`, `/api/events` HTTP 200을 확인했습니다. 실제 사용자 인증·AI 모델 호출·브라우저 비동기 시험·배포·18단계 심판 판정은 미실행입니다. 100점이나 운영 연결 완료를 주장하지 않습니다.

실행: Node.js 24.19.0을 준비하고 `cd on-client && npm run demo`로 예제 앱을 연 뒤 보안 기록의 설명 요청을 확인합니다. 실제 연결은 별도 어댑터·앱 권한이 필요합니다. 정상 합성 설명은 해당 사건의 근거와 규칙을 표시하고, 없는 근거 ID·실패 응답은 설명을 거부해야 합니다. 키나 토큰을 코드에 입력하지 않습니다.

### 18단계 오류 안내 수정 · 전체 조건 재점검

심판 커밋 `75c8f1cab561`은 8개 중 7개 항목 통과, insufficient_evidence 한 항목 실패입니다. 오류 분기가 제공 코드의 안전한 error.message까지 고정 안내로 바꾸어 구체적인 근거 부족 사유를 지웠습니다. 오류 문구의 안전성·길이·제어문자·비밀값 형태를 확인한 뒤 안전한 원문은 textContent로 표시하며, 누락·안전 미확인은 고정 안내로 대체합니다. 오류 코드 허용 목록과 실패 시 성공 속성 제거는 유지합니다.

전체 8개 필수 기준을 독립 검토하고 합성 DOM 시험 17건을 실행해 모두 통과했습니다. 같은 시험을 수정 전 코드에 적용하면 안전한 구체 메시지와 HTML 문자 보존 2건이 실패하여 원인을 재현했습니다. JWT·이메일 형태의 오류 반사도 차단합니다. 이전 시험에는 안전한 오류 메시지 보존 검사가 빠져 있었습니다. 제공 서버·앱 연결·앞 단계 함수·자료실·DB는 수정하지 않았습니다. 실제 모델 호출과 수정본 심판 통과는 이 로컬 시험의 증거가 아닙니다.
