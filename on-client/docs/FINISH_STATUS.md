# 완성본 작업 기록 · 검증 중

선택: 관제 대시보드형 + 기본 포장·바로가기. 기준 원격 소스: `843906edcb465d857ba377e78a99fc504eb53445`. 기존 13~22단계 학생 함수와 이전 제출 기록을 보존했습니다.

## 실제로 확인한 범위

- macOS / Node.js 22.22.2에서 기존 40건과 새 관제·포장 시험을 합쳐 57건 통과했습니다. 수업 기준 Node.js 24.19.0 및 Windows 실행과 구분합니다.
- 브라우저에서 예제 허용·거부·추가 확인 표시와, 개선 후 4개 상태 카드·수동 기기/세션 조회를 확인했습니다. 예제(demo)는 실제 회사 시스템 연결이나 PC 실측이 아닙니다.
- 기기·세션·알림·SDP 점검 응답을 구분합니다. 수동 보조 조회는 학생 영역만 갱신합니다. 전체 상태 갱신은 기존 상단 「다시 불러오기」와 「도움정보 불러오기」를 사용합니다.
- 비동기 조회의 중복 실행·이전 응답 반영·화면 변경 후 버튼 잠김과 연결 상태값을 검사했습니다. 제공 서버·인증·공통 화면·CSS·보안 정책은 변경하지 않았습니다.
- DOM 가상 시험만으로는 CSP에 의한 inline 스타일 차단을 찾지 못했습니다. 브라우저에서 발견한 뒤 기존 grid-2/card/btn 클래스로 고치고 재확인했습니다. 좁은 창에서 제공 화면의 최소 너비 제약은 남아 있습니다.

## 핵심 기능 세 가지

1. 사용자·기기·세션과 업무 앱의 허용/거부/추가 확인 현황.
2. 보안 기록의 근거·규칙과 참고용 AI 설명. 실제 AI 연결 실패와 업무 판정을 분리합니다.
3. 조치 제안, 사람 확인, 접수와 실제 효과 확인을 구분합니다. 화면 요약은 조치를 실행하지 않습니다.

## 실행과 다시 확인

Node.js 수업 기준은 24.19.0입니다. `on-client` 폴더에서 `npm test`, `npm run check`로 검사합니다. `npm run demo` 후 http://127.0.0.1:5189 를 열면 예제 화면입니다. 상단에서 보호 현황 → 학생 상태 영역 → 「기기·세션 보조 조회」를 누르세요. 출처·시각·unknown을 확인합니다. 업무 앱의 허용/거부/추가 확인은 각각 예제 정책 결과이며 실제 접속 권한 변경이 아닙니다. 종료는 Ctrl+C입니다.

소스 포장은 `npm run package:portable -- --out <아직 없는 출력 폴더>`입니다. 출력 상위 폴더는 미리 있어야 하며 프로젝트 내부 출력은 거부합니다. 정확한 포함·제외 파일과 새 폴더 실행은 [포장 안내](PORTABLE_PACKAGE.md)를 따릅니다. 학생용 source-app.tar.gz와 PORTABLE_SOURCE_MANIFEST.json은 수업의 app.zip·APP_PACKAGE_MANIFEST.json·finish.commit.raw·finish.archive.tar.gz를 대신하지 않습니다. .cmd/.sh 시작기는 Node가 설치된 PC에서 예제 서버를 시작하는 스크립트이며 승인된 host나 Windows .lnk 바로가기가 아닙니다.

공식 포장·실제 계정·유료 AI·실제 보안 조치·PC 수치·Windows 시험·최종 제출·점수는 이번 작업에서 실행하지 않았습니다. 이전 22단계 기록의 완료와 이 완성본 실행 검증은 구분합니다. v1.0 또는 운영 완성으로 표시하지 않습니다.
