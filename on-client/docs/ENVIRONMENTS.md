# 환경을 나누어 실행하기

서로 다른 환경의 작업물을 같은 저장소에 보존할 수 있지만 서버 설정이나 자격을 PC 사이에 복사해 자동 연결하지 않습니다.

| 영역 | 실행 환경 | 원천과 제한 |
|---|---|---|
| 저장소 루트 자료실 | Vercel / Node22이상, 기존 서버 DB | 기존 웹 배포. PC 센서를 배포 서버에서 돌리지 않음 |
| on-client 제공 앱 | Node24.19.0 기준 | 기존 시작/예제 기능, 학생 PC 경로 없음 |
| on-client 학생 앱 | Node24.19.0~24.x | 127.0.0.1 로컬 전용. 실행한 PC에서 수동 읽기 |
| macOS/Linux | 위 학생 앱 | CPU·메모리·디스크·구성 개수. Windows 항목은 확인 불가 |
| Windows | 위 학생 앱 | 고정 C:\Windows PowerShell 읽기. 다른 설치 위치·권한·정책이면 확인 불가. 관리자 승격하지 않음 |

## 확인된 결과

macOS의 Node22.22.2는 이전 개발 시험 환경이며 지원 범위와 구분합니다. 별도 임시 Node24.19.0에서도 환경 진단 OK, 전체93개 시험 통과, 실제 PC 읽기 상태를 확인했습니다. Node24.x 이후 다른 주 버전은 이 지원 선언의 대상이 아닙니다. 실제 Windows 실행은 사용자 확인 대기입니다.

## Windows 시작

Git과 Node24.19.0이상24.x를 준비하고, CMD에서 새 폴더에 받습니다.

```bat
git clone https://github.com/jjeya-hannam/choi-bujang-secret-vault.git gamst-windows-env
cd gamst-windows-env\on-client
tools\start-portable.cmd
```

폴더가 있으면 지우지 말고 다른 새 이름을 사용합니다. 시작기는 Node버전·SQLite·statfs를 먼저 확인합니다. 이 프로세스의 ON_PORT를5189로 고정해 다른 PC에서 남은 환경변수와 주소 안내가 엇갈리지 않게 합니다. 포트를 사용 중이면 다른 프로세스를 죽이거나 방화벽을 바꾸지 말고 첫 오류를 확인합니다. 실패 종료 코드는 보존합니다.

브라우저에서 http://127.0.0.1:5189 를 열고 「내 PC 상태 조회」를 누릅니다. 실측과 예제 보안 기록은 별도입니다. `npm run environment:check`는 환경값·사용자 경로·키를 출력하지 않는 진단입니다. 포트 사용 가능성과 Windows 명령 권한은 단순 진단의 성공으로 입증하지 않습니다.

기존 폴더에서 이어받을 때는 먼저 git status를 확인하세요. 로컬 변경이 있으면 덮어쓰지 말고 새 clone에서 확인합니다. 기존 .env·DB·자격·보관함·사용자 기록을 새 PC나 패키지에 복사하지 않습니다. 옛 단계의 소스 manifest는 당시 저장점의 증거이며 현재 실행 묶음의 manifest와 섞지 않습니다.

공식 승인 host·최종 제출4파일은 별도이며 학생 실행 묶음으로 대체했다고 주장하지 않습니다. 실제 Windows 결과에서 성공·권한 거부·확인 불가를 구분해 기록합니다.
